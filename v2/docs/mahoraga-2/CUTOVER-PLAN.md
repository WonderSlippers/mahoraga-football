## 已执行的恢复方式

停止本次新站自身的写入进程后，`npm run backup:verify -- research` 按每页 128 行导出各业务表 JSONL，记录每表 SHA256/行数。恢复到另一全新 D1 身份，重新打开后再次逐表哈希验证。

恢复目标在全部验证完成前标记 `restorationState=IN_PROGRESS`；启动器拒绝启动该状态。禁止对非空库直接恢复。备份不带会话和服务令牌，目标重新生成本地凭据。上述步骤不打开旧站 D1，也不复制运行中的旧 SQLite 文件。

## 回滚与新写入保全

先停新增写入，再导出切换后全部原票和追加事件，记录新旧水位与 SHA256。代码回滚不能覆盖数据库或删除新事件。默认回滚到“旧 UI 只读 + 新账本保留且只读”的状态。

若旧程序不能理解新事件，禁止恢复旧写入或把过期余额当可用资金；需要另行验证反向转换与逐笔对账。不得做破坏性 down migration，不得用旧备份覆盖含新票的数据库。

## 可执行命令的适用范围

`stop:v2` / `stop:research` 只通过本次 supervisor 的运行身份接口停止其自有进程。`backup:verify` 只接受新 v2 `.runtime-v2/` 下的 profile。任何旧站停写、旧任务改动、push 或部署均没有对应自动步骤。
